# 測定と因果の切り分け

## 比較条件

対象の版・URL・操作、時刻と地域、端末・ブラウザ・回線、認証状態、データ規模、キャッシュ条件、起動状態を、判断に必要な範囲で残す。未確認を推測で埋めない。

同じ操作を少数回繰り返し、個々の値と中央値・範囲を見る。最初の試行を隠して平均だけを出さない。初回と再訪、命中と不命中、起動直後と稼働中は別の標本にする。実利用の分布が必要なら、プライバシーに配慮した既存のRUMやログを利用する。

| 調べたいこと | 観測 | 注意点 |
| --- | --- | --- |
| 最初の画面 | Navigation / Resource Timing、FCP・LCP、画面 | APIだけの速度では判断できない |
| 操作への反応 | 操作トレース、長いタスク、INPの実利用データ | 単発の操作時間を集計済みINPと呼ばない |
| API | クライアント計測と要求IDに対応するサーバートレース | ネットワークとサーバー実行時間を分ける |
| DB | クエリ回数、実行計画、待機、接続プール | EXPLAIN ANALYZEは実行を伴う。本番の書き込み・重い処理に注意 |
| キャッシュ | Age等のヘッダー、命中記録、比較条件 | ヘッダーだけで全階層の命中を断定しない |
| 休止後 | 起動ログと最初の実アクセス | 連続測定では本当の休止後アクセスは再現できない |

キャッシュ回避のランダムなクエリ追加は、アプリの条件・SEO処理・DBキャッシュキーを変えることがある。ブラウザのキャッシュ無効化もCDNやDBの無効化とは異なる。

## 小規模HTTPプローブ

Python 3.10以上、追加依存なし。スキルのディレクトリで実行する。

```sh
python scripts/http_probe.py https://example.com/ --count 3 --interval 1
```

- 公開されている読み取り専用URLを指定する。GETでも業務実行やリンクトークン消費を伴うURLには使わない。
- 認証、Cookie、任意ヘッダー、リダイレクト追従には非対応。URL中のユーザー情報は拒否する。クエリに秘密を入れない。
- 最大10回、逐次実行。既定は3回・間隔1秒。タイムアウトは各ソケット操作の上限で、遅いストリーム全体の絶対上限ではない。
- URL・本文・Cookie・生の例外文字列はJSONに出さない。対象識別情報は共有先に合わせて別に記録する。
- `headers_ms` は開始からレスポンスヘッダー取得まで。厳密なTTFBではない。`total_ms` は本文取得完了または上限到達まで。
- 3xxは追従せず記録する。4xx・5xx、通信エラー、本文上限超過を正常標本に混ぜない。完全に取得できた2xxも業務上の成功を保証しない。
- 接続再利用やブラウザキャッシュを再現しない。JavaScriptを動かさず、画像も取得しない。描画、LCP、操作応答や負荷耐性は別に測る。

仮説を区別できる証拠と必要な比較がそろったら止める。原因が未確定なら残る候補と必要な観測を示す。調査を理由に大量アクセスしたり、本番を止めてコールド状態を作ったりしない。
